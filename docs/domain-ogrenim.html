2) İki kritik kavram

NameServer (NS)

“Bu domainin DNS defteri nerede tutuluyor?” sorusudur.

  • Bizde: tr/us/eu.dnsenable.com
  • Defter İsimTescil/DnsEnable’da kalır
  • Bunu Vercel NS’e çevirmek zorunda değildik

DNS kayıtları (A / CNAME)

“Defterin içindeki satırlar nereye gitsin?” sorusudur.

  • A: isim → IP
  • CNAME: isim → başka isim
  • Vercel’e bağlamak için asıl iş burasıydı

3) Neden NameServer değiştirmedik?

Yanlış deneme

NS’i ns1/ns2.vercel-dns.com yapmak.

  • Vercel o zone’u hazırlamadan REFUSED döndü
  • İnternet SERVFAIL gördü
  • Site hiç açılamadı

Doğru yöntem (Method A)

NS DnsEnable’da kaldı; sadece A/CNAME değişti.

  • E-posta MX kayıtları korunur
  • Daha az riskli
  • Onaysız NS değişimi yapılmadı

5) Vercel tarafında ne yaptık?

Proje & domain

  • Doğru proje: yazilim-sitesi
  • halilmertdeveli.com.tr eklendi → ana domain
  • www → apex’e 308 redirect
  • yazilim-sitesi.vercel.app silinmedi

SSL & HTTPS

  • DNS doğru olunca Vercel sertifika kesti
  • Let’s Encrypt · CN = apex
  • HTTP otomatik HTTPS’e 308

6) Kod tarafı neden kolaydı?

  • Site:PublicBaseUrl = https://halilmertdeveli.com.tr zaten vardı
  • Canonical / OpenGraph bu değeri kullanıyor
  • OAuth / CORS callback yoktu → provider paneli işi çıkmadı
  • AllowedHosts = * (Vercel hostname’leri kırılmasın diye)

Yani asıl iş kodda URL değiştirmek değil, DNS + Vercel domain eşlemesiydi.

7) Ana mantık (ezberlenecek cümleler)

Domain ≠ Hosting

Domain sadece isimdir. Hosting Vercel’de kaldı; ismi Vercel’e işaret ettik.

NS ≠ A kaydı

NS defterin yeridir. A/CNAME defterdeki satırlardır. Biz satırları değiştirdik.

Canonical tek olmalı

Tek doğru adres: apex. www sadece oraya yönlendirir.

Eski URL yedek kapı

*.vercel.app production’ı bozmadan yeni domaini bağladık.

8) Transfer kilidi neden önemsizdi?

Transfer Kilidi domaini başka firmaya taşımayı engeller. DNS/A kaydı / Vercel bağlantısı ile ilgisi yoktur. Kapalı kalması domain geçişini engellemez.
